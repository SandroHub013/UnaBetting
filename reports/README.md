# reports/

Two kinds of file live in this folder, and confusing them is how a project like this
one ends up lying about itself. Read the split before citing anything from here.

## Archived — pre-leak-fix. Do not cite.

`index.html`, the six `chart_*.png`, `PAPER_MIGLIORAMENTO.md` and
`Tennis_Prediction_Academic_Presentation.pptx` were produced in May–June 2026,
**before** three data leaks were found and fixed. They report **78.8% accuracy** and
**+56.2% ROI**. Neither number is a result; both are the leak.

| when | the leak | what it inflated |
|---|---|---|
| 2026-05-21 | Medians computed over the full dataset, so the future entered training. | accuracy **78.8%** → fixed with train-only medians |
| 2026-05-22 | A winner-side feature with no loser twin, which reconstructs the target through the perspective flip. | ROI **+46%** → fixed by enforcing perspective pairs |
| 2026-06-09 | No scaler, un-randomised rows, phantom even-money odds. | win rate **85%** → the honest re-run came back at **−92% ROI** |

The charts have a second problem on top of that one: **their values were never read
from a run at all.** `scripts/diagnostics/generate_charts.py` and `generate_pptx.py`
carry them as literals —

```python
accuracy = [74.2, 76.1, 78.8, 77.5, 77.9]      # generate_charts.py
roi      = [56.2, 31.0, 49.8]
```

— and both write to a hard-coded `OUTDIR` on a drive that is not part of this
project, so neither script can be re-run in place to check.

They are kept rather than deleted because this project's history **is** the leak hunt:
the chronology above is published on the website on purpose. An artifact that shows
what a leak looks like is worth having. An artifact that shows it *without saying so*
is not — which is what the banner at the top of `index.html` is for.

## Current — written by the pipeline

| File | Written by | What it is |
|---|---|---|
| `metrics_history.csv` | `scripts/log_metrics_history.py` | One row appended per training run, from `models/atp_metrics.json` |
| `last_backtest.json` | `python -m src.models.backtest` | The most recent honest backtest |
| `results_feedback.csv` | `scripts/check_results.py` | Realised outcomes checked back against the predictions |
| `reviews/` | — | PR review notes, kept as a record |
| `atp_backtest.csv` | — | A per-bet trace, 2024-01-01 → 2026-01-13, bankroll 1000 → 344. No current script writes this filename; treat its provenance as unpinned. |

## The honest numbers, and one discrepancy worth naming

The README headline comes from `models/atp_metrics.json` — gitignored, regenerated by
`scripts/publish_metrics.py`: **67.4% accuracy, log loss 0.601, ROC 0.740, backtest
ROI −29%**. `metrics_history.csv` agrees on the model side; its last row reads
`0.673561` accuracy, `0.600585` log loss, `0.739764` ROC.

`last_backtest.json` does **not** agree on the financial side. Its 2026-06-12 run
records 2801 matches, 458 bets and **−7.3% ROI**, not −29%. They are different runs
and nothing in the repository reconciles them. Until something does, cite the file you
actually read rather than the number you remember.

## What it would take to trust the charts again

Rewrite the two diagnostics scripts to read `models/atp_metrics.json`,
`reports/last_backtest.json` and `reports/metrics_history.csv` instead of literals,
drop the absolute `OUTDIR`, and regenerate after a real `train` + `backtest`. Until
that happens, every figure in the archived set is an illustration of a bug — which is
the one thing it is still honestly good for.
